# 独立持久见证隔离实验

作者：Wang Lu。2026-11-09。NAS R2 已由操作员实际执行，18 项实时观察测试全部通过；NAS 普通读写不依赖 Mac 的策略不变。本轮补充独立持久见证状态，不部署网络服务，不生成生产见证密钥。

## 状态、签名器和事务

`scripts/recovery_durable_live_witness.py` 的 `DurableLiveWitness` 复用既有 `DurableWitnessReader` 的私有 SQLite 签名证明存储实现，通过组合使用其连接、历史签名验证与 FULL commit；没有改变原 reader 的公开语义。见证目录 0700、数据库 0600，保存固定 trust 和经过签名的头元数据，没有源目录路径、记忆正文、Owner/Avatar 私钥或见证私钥。此复用是实验内部依赖，尚不是稳定的服务存储接口。

调用者从外部提供 signer，公钥必须匹配已固定的 trust。打开已有见证不会创建数据库、替换密钥或生成新 generation；状态丢失、损坏、未知 Schema 或错误 signer 时拒绝。首次登记必须显式提供独立取得的初始头摘要、对应 nonce 和有效证明，不覆盖已有目录。

每次回答在 `BEGIN IMMEDIATE` 下重新读取已提交的头，验证当前 nonce 绑定的源观察，再计算新头并调用外部 signer。生成的证明也必须通过签名/范围/高水位验证，才能写入 SQLite。提交完成并再次检查时效后才返回证明。源观察过期、错误 signer 或旧状态不得得到成功回答。

提交前失败回滚，重启读取旧头；提交后响应失败保留新头，用新的实时源观察重试同一检查点不会重复推进序号。历史证明即使过期仍可验证存储的历史头，但不能当作新请求的源观察。普通 NAS 写入完全不引用这个数据库，不等待 Mac。

## 验收与限制

16 项新测试覆盖重开与真正的新 Python 进程读取、两个写入者竞争 SQLite 写锁后重新核对高水位、旧实例、提交前/后异常、提交后过期、错误及异常签名器、损坏签名、缺失/未知存储、显式首次登记、私有目录模式和无私钥/正文/token 持久化。全 scripts/tests 加下述公开身份采集合计 139 项。

这里的崩溃边界使用可控异常注入；不据此宣称整机断电、硬件缓存或任意文件系统的耐久保证。源和见证存储整体回退后，如果另一个独立 reader 仍保有更高已见头，会拒绝旧证明；若其高水位也丢失，旧签名状态仍可能被接受，该负例固定在测试中。实时观察后的并发源修改以及未见离线历史的限制仍见[可用性实验](RECOVERY_AVAILABILITY_CN.md)。

本阶段不包含生产 Keychain 签名器；后续[只新增钥匙串签名器](MAC_KEYCHAIN_SIGNER_CN.md)已完成准备代码与测试，真实凭据创建尚待明确确认。独立守护服务、认证传输、密钥轮换/丢失恢复、激活许可或持续撤销仍未完成。本阶段测试 signer 是合成的内存 Ed25519 密钥；进程重启测试通过匿名 stdin 传递测试密钥，不把它写进见证库。不能把外部 signer 参数本身当成已经实现了安全密钥托管。

## 真实登记前先确认公开身份

`scripts/inspect_core_identity.py` 只读固定 Schema 和 `meta` 表中的 `avatar`、`owner`、`enrollment` 三项公开登记元数据（单值上限 64 KiB），验证本地 enrollment 的 Ed25519 签名及身份引用对应关系，仅输出引用、登记摘要和两类公钥摘要。它不选择 memories、grants 等应用表的行，不读取私钥文件、token 文件、环境变量或历史备份。

该工具使用 `mode=ro`、query_only、只读事务，拒绝未知 Schema、符号链接、WAL/SHM/journal 旁文件和缺失数据库，不创建或清理数据。4 项测试覆盖没有私钥文件仍可核对、源文件摘要不变及无正文/token输出、异常路径/旁文件、签名篡改和类似内部表名的未知 Schema。不可用不等于空状态，可稍后重试，不应停机或清理旁文件来迁就采集。

本地登记签名只说明此记录内部可验证，不证明全球身份或法律所有权。操作员必须通过可信 NAS 终端核对“这是计划绑定的活跃 Core”，再把摘要用于后续可审阅的信任配置；采集输出本身不授权写 Keychain、登记见证信任根或更换生产服务。真实设备引用与指纹只保留在私有工作区。
