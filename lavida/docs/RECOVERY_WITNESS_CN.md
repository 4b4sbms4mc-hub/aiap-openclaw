# 合成独立见证状态机实验

作者：Wang Lu。2026-11-09。`scripts/recovery_witness.py` 是仓库内、单线程、内存状态的协议实验；不是独立设备上的见证服务、持久化账本、生产最新性来源或恢复激活授权。Core 0.2.0 和插件 0.3.5 源码候选版本均不变。原[设计提案](RECOVERY_LEDGER_DESIGN_DRAFT_CN.md)仍有待实现部分。

## 本轮可验证行为

- `SyntheticWitness` 使用临时独立 Ed25519 密钥和随机 generation；Avatar、enrollment 摘要和见证公钥由实验外明确登记，而不是从待恢复备份自动信任。
- `begin_update(expected_sequence)` 为源变更预先设置 pending。pending 时禁止返回证明；检查点验证或发布失败保持 pending，没有“取消后继续旧头”的捷径。旧写入序号、错误 ticket 和已提交 ticket 重用均拒绝。
- `publish` 验证真实 Owner 签名检查点和身份，推进序号与前头摘要，并拒绝 Core revision / revocation epoch 倒退；计数不变时治理内容必须一致，允许只刷新检查点时间。
- 每次证明绑定随机 nonce、签名治理头和最多 60 秒有效期，不能超过检查点有效期。恢复端使用预先登记的公钥、generation 与 enrollment 验证；挑战在一次验证尝试后消耗，失败也不能重用。
- 仍在同一进程中的恢复端记住已见头，拒绝序号倒退、相同序号分叉和相邻条目的错误前头摘要。跳过多个序号时仅验证受信见证签名与单调计数，不宣称已验证完整历史哈希链。
- 验证结果仅是选定检查点的 SHA256，交给既有隔离恢复工具再次校验输入；不生成生产激活令牌、不启动 Core 或 Gateway、不授予见证写入权。

## 验收与明确负例

16 项见证测试和原 22 项恢复测试共 38 项通过。真实检查点/签名/SQLite 隔离恢复闭环确认保留一项当前记录、排除后来删除及过时项、旧 Owner/adapter token 失效、源快照不变。覆盖 pending/错误 ticket、检查点替换、旧检查点提交、nonce 重放、错误签名/身份/generation、公钥替换、过期/未来/过长证明、已见序号回退、分叉、元数据不携带正文或 token、严格整数和刷新语义。

其中两项是**限制负例**：

1. 源端未先标记 pending 就发生删除，见证仍可返回它所知的旧头，实际隔离恢复可重新出现已删除记录。此实验没有将 Core 数据事务与见证推进强制绑定；即使标记 pending，若生产方提交旧检查点，见证也没有独立读取源端来判断其真实性。因此不能声称它解决了源事务和账本一致性。
2. 见证状态被回退且恢复端新建、没有持久化已见头时，仍可能接受以原见证密钥新签出的旧头。随机 nonce 防止原样重放旧响应，不能阻止受信见证重新签署旧状态。内存模型不提供重启后的防回退保证。

调用者拿到 pin 后，治理头仍可继续更新。此实验没有激活前二次读取、持续撤销传播、可信时钟、持久化/崩溃恢复、并发互斥、网络身份认证、见证密钥轮换或丢失恢复。见证不可达或不可信时，不得回退为“自动信任备份”；当前代码不含远程传输或无人值守部署入口。

## 重现

在仓库根目录使用安装了 `lavida/core/requirements.txt` 的 Python 3.12 环境运行：

```sh
python -m unittest discover -s scripts/tests -v
```

所有数据和密钥均由临时合成夹具生成并清理。该命令不访问 NAS、邮箱、模型或任何远程见证。
