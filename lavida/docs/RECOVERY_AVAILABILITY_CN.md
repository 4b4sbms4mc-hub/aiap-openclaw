# NAS 独立运行与恢复时实时核对

作者：Wang Lu。2026-11-09。用户已选择：Mac 关机、休眠或断网时，NAS 日常读写继续；恢复验证缺少新鲜证明时拒绝。这是可用性策略和隔离实验，尚未接入生产服务。

## 本轮实现

`scripts/recovery_live_observation.py` 在合成 Core 上实现一次实时核对：恢复端产生新的随机 nonce；源端在只读 SQLite 事务中将指定检查点的治理摘要与当前源状态比较，吻合后用源端 Owner 密钥签署绑定 nonce、检查点摘要、enrollment 摘要和最多 30 秒有效期的观察结果。该签名使用独立域，不与既有检查点或见证签名混用。

Mac 侧实验见证先验证预登记 enrollment、源签名、nonce、检查点与时间范围，再按现有序号/治理计数高水位规则发布头并回答。即使检查点未变，每次回答也必须取得该 nonce 对应的源观察，不能仅从旧头回答。见证证明的到期时间不得晚于源观察或检查点。恢复端仍须验证见证签名并消费自己的挑战；输出只用于检查点选择，不是激活许可。

日常 Core `Service` 完全不依赖该见证。Mac 离线期间批准、删除和撤销不会等待 Mac；重连时，离线前的检查点若不再对应当前源，源观察拒绝。显式导出当前检查点后再观察，才可按新状态选择恢复检查点。源观察不返回记忆正文、token 或私钥，但它在源端需要读取 Owner 私钥，**不同于只读取公共程序/Schema 的 NAS 预检工具**；本轮只对合成夹具运行，没有在 NAS 执行该观察程序或授权生产密钥访问。

SQLite 观察使用 `mode=ro`、`query_only`、只读事务和完整已知 Schema 比较，不创建缺失数据库。当前仅支持无 WAL/SHM/journal 旁文件的实验夹具；发现旁文件即拒绝，不清理旁文件，不声称覆盖实际运行中的所有 SQLite 模式。

## 保证与边界

| 场景 | 本轮行为 |
|---|---|
| Mac 不可用 | NAS 日常操作继续；无法取得见证证明则恢复验证拒绝 |
| NAS 不可用或无当前 nonce 的观察 | 不能用缓存头放行恢复选择 |
| 离线后删除或撤销，拿旧检查点观察 | 当前源摘要不同，拒绝；当前检查点含删除/撤销状态 |
| 重放其他 nonce、篡改、错误 enrollment、过期或时钟回退 | 拒绝；见证证明不延长源观察寿命 |
| 源回退到见证已观察过的更低状态 | 见证计数高水位拒绝，不自动重新登记 |
| Mac 未见某次离线变更，源在重连前整体回退 | **可能检测不到**；回退后的源仍能对新 nonce 签名 |
| 观察完成后源又发生变化 | **已有证明不自动失效**；这是时间点观察，不是写锁、租约或持续撤销机制 |
| 重建实验见证 | 新密钥/generation 不被原 reader 自动接受；无静默信任根替换 |

后两项风险由真实负例固定在测试中。可用性优先模式不能同时宣称“见证必然记录所有离线变更”。若要更强保证，需要额外独立且不可回退的源端历史依据，或重新选择会影响写入可用性的同步策略。签名、nonce 和 TTL 各自不能解决源与未见历史共同回退的问题。

## 验收与后续接入门槛

18 项新测试包含：普通 Core 离线删除/撤销继续、旧检查点拒绝、当前删除检查点实际恢复后不复活、观察前后合成源文件摘要不变、不返回正文/token/私钥、nonce 重放、签名/范围/时效、未知 Schema/旁文件/符号链接/缺失 DB、持久 reader 接受及新见证信任根拒绝，以及上述两个限制的负例。与既有 101 项合计 119 项。

目前见证仍是内存状态机，没有实现跨设备认证传输、独立持久化见证头与安全签名器、源端 restricted endpoint、Mac 钥匙串密钥托管、轮换及控制丢失处理，也没有恢复激活前的再次核对与后续撤销。现有 `SourceGate` 是另一种同机同步实验，不会因本轮代码而改变生产写入。

接入前应先完成可审阅的配置与隔离端到端验收包：限定的源端命令和消息大小/超时、SSH 主机和客户端公钥固定、禁止任意 shell/转发、只读 volume 与密钥访问清单、Mac 本地持久目录与签名器、启动/停用/回退步骤。实际部署须另行确认具体变更；本轮策略确认和只读预检不代替生产授权。

NAS 的下一步仅进行容器隔离验收，入口为 `sh scripts/run_nas_observation_lab.sh [已存在的本地Core镜像]`。它拒绝非 Linux，使用 `--pull never`，新建自动删除的临时容器，以 UID 10001、无网络、只读根目录、无 capabilities、禁止提权、限定内存/CPU/PID 运行 18 项实验测试。唯一宿主机挂载是测试包本身（只读），合成状态只写入容器 `/tmp` 的 256 MiB tmpfs，不挂载生产 `/data`、Docker socket、Mac 目录或历史备份。不会重启、修改或删除既有容器/镜像/数据卷，不开放端口，也不创建见证服务或信任根。异常强制中断时可由 NAS 管理员核对本次临时容器，不执行全局清理命令。

该脚本也在 Linux CI 的已构建 Core 镜像上执行，属于容器环境验收，不能代替用户 NAS 上的实际运行结果。NAS 验收输出只需保留镜像 ID、18 项测试汇总和结束标记，不发送密码或密钥。
