# 检查点安全续期与控制丢失审阅实验

作者：Wang Lu。2026-11-09。本增量继续使用仓库内的同机 POSIX 隔离实验，不接入生产 Core/HTTP/Gateway/NAS。组件版本和已发布资产不变。它没有部署独立见证服务，也不自动重建失去的信任根。

## 显式续期契约

`SourceGate.refresh(expected_sequence)` 必须由调用方显式发起；没有后台续期任务。源数据、记忆、身份、授权、grant 到期、Core revision 和撤销 epoch 均不因续期而修改。只有新的签名检查点时间/摘要、见证序号与前头链发生变化。

调用者须提供严格整数且等于当前头的 expected_sequence。操作持同一 gate flock，拒绝 pending、旧序号、丢失/被替换的当前检查点、签发前时钟、源治理或身份不符。旧检查点即使已过期，仍可在其原签发时间验证历史签名；这个历史验证不等于确认当前性，当前性依赖受信实际源的一致性检查。

验证旧签名检查点与已发布头的 enrollment/治理摘要、revision、epoch 和时间绑定后，重新核对实际源。先保存 pending，再从真实源导出新检查点。发布前再次核对捕获的检查点与实际源，并持有源 SQLite 写锁直到新头保存完成；续期还要求治理摘要与续期前一致，不能借续期悄悄接纳源端新变更。

过程中失败保留 pending，显式 resync 才能从实际已提交源恢复。resync 不重放源动作、不接收调用方旧检查点；ready 状态下它不代替 refresh 自动延长 TTL。发布后响应丢失时，先检查当前序号，不可用旧 expected_sequence 盲目重试。两个并发续期者使用同一旧序号时只能一个发布成功。

源锁只保证本机 SQLite 事务期间的协调，仍不提供证明返回后持续授权、跨设备互斥或可信时钟。源/控制状态整体回退、恶意同用户/管理员和旧证明窗口等原有限制继续成立。

## 控制存储丢失时的只读证据

`review_control_loss(source_dir, control_dir, reader)` 要求独立保存的 `DurableWitnessReader` 仍可验证已见头，并读取停机一致源快照。reader 不得放在待检查源或控制目录内。函数拒绝活动 WAL/SHM/journal、未知 Schema、错误签名/身份、正文摘要不符、权限不符和符号链接。

报告区分目录/状态/锁缺失、损坏状态、尚未另行认证的现有状态。对照已见头，低于已见 Core revision/epoch 或相同计数却治理摘要不同的源标记为 blocked。源计数相等或更高也只标记 manual-owner-review-required，不能证明它是实际最新状态。

报告不创建目录、见证私钥、检查点、凭证或替代状态；不读取源私钥即可验签，不修改源或 reader。输出不含记忆正文、token 或见证私钥。`automatic_reenrollment` 与 `proofs_may_resume` 始终为 false。reader 自己丢失时也不回退为信任备份；必须另行由 Owner 通过独立可信渠道处理。

## 验收

10 项续期测试 + 12 项丢失审阅测试，加原 74 项，共 96 项本地通过。

- 过期检查点成功续期且源文件摘要、身份、Core revision、epoch、grant 均不变；持久化 reader 接受新的后继头。
- 严格 CAS、pending、时钟回拨、旧检查点丢失/替换、实际源改变、pending 保存失败均拒绝；捕获检查点后源被绕行修改也拒绝发布。
- 三个续期阶段真实子进程 SIGKILL 后保留 pending/已发布头；两个真实续期进程竞争同一旧序号仅一个成功。首次独立场景共用了reader导致正确分叉拒绝，修正夹具为独立reader后通过，未放宽实现。
- 丢目录/状态/锁、损坏状态、源快照回退/同计数分叉、无私钥快照、错误身份/正文、活动旁文件/未知Schema/符号链接、reader丢失和目录重叠均按约定拒绝或仅报告。核对源/reader文件不变，不产生新密钥或恢复权限。

复现（仓库根目录，Python 3.12 + Core requirements）：

```sh
python -m unittest discover -s scripts/tests -v
```

LM Studio `qwen2.5-coder-14b-instruct-mlx` 提供部分续期验收建议；Codex 采用历史签名、当前源一致性和序号方向，未采用“pending 本身已有签名”等不符合当前实现的建议。代码、最终测试和复核由 Codex 完成；丢失审阅阶段未另调用模型，未调用云端模型。

## 进入独立部署前仍需确定的事项

以下是下一阶段设计输入，不是已满足的生产条件：

| 待确认项 | 决定什么 |
| --- | --- |
| 独立见证设备或服务、操作系统及网络边界 | 不能把同机 flock/目录隔离直接推广为跨设备协调 |
| 设备/服务保管方与 Owner 的关系 | 明确谁有权登记、停用、迁移见证及恢复丢失状态 |
| 见证密钥的安全托管位置与轮换方式 | 当前合成实验的0600明文密钥文件不应直接投入生产 |
| 初始公钥/generation/已见头的独立确认渠道 | 防止从旧备份同时导入旧信任根并自称当前 |
| 允许的生产入口、部署和恢复范围 | 尚须实现认证通道、所有写入入口接入、激活与后续撤销策略 |
